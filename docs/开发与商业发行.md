# 开发与商业发行

## v0.4.0 购前检测与 Intel 路线

当前构建目标：Mac arm64、Mac x64（Intel CPU）、Windows x64（CPU）。Mac 需要 macOS 14+，Windows 需要 Windows 10 2004+。Intel 使用 `requirements-intel.lock`（PyTorch 2.2.2、NumPy 1.26.4、ONNX Runtime 1.19.2），不得复用 Windows 锁文件。Windows ARM、Linux、鸿蒙未适配。Intel 与 Windows 物理机验收仍待完成。

未激活允许配置检查、组件与模型准备、固定文案试音及报告复制；自由配音、普通 setup、声音导入、作品和录音仍锁定。worker 的 diagnose 忽略客户文案，仅生成固定检测文案，保存至 preflight/，不写作品历史。四项功能单独验证，报告仅声明所选且通过的功能。

准备使用同一个跨进程锁，可取消重试。组件按架构和依赖锁哈希标记；模型下载固定仓库提交并校验 SHA-256，完成标记原子写入。已校验模型可离线复测。Windows 当前自动安装 CPU 版 PyTorch，不包含 CUDA 加速；现有运行时代码的 CUDA 分支不代表已交付可用的 GPU 安装配置。支持 CUDA 前必须增加独立安装 profile、依赖锁与驱动/显存验收，当前仅按 CPU 实测耗时出具报告。购前模型和组件目录可在首次准备前另选，作品与授权路径不变。

下载源集中在 `shared/download-sources.json`：模型按魔搭 → HF-Mirror → Hugging Face，Python 按 npmmirror → Astral → GitHub，依赖按清华 → 阿里 → PyPI 自动切换。`shared/model-manifest.json` 逐文件固定 Hugging Face / 魔搭提交、大小和 SHA-256，配置与 tokenizer 也纳入校验；不依赖浮动 master。相同文件的临时下载可跨源续传，兼容旧 Hugging Face 权重临时文件；服务器忽略 Range 时安全重下，损坏文件清理后换源，磁盘和权限错误直接报告。各平台沿用独立依赖锁，Windows 的 sox 固定 1.4.1 通用 wheel，避免 1.5.0 仅源码分发导致首次安装失败。

`npm test` 包含下载故障、切源、校验和组件恢复测试；`npm run test:downloads:real` 不借用开发 Python 或既有模型，在新目录实际安装组件、下载轻量包、中断续传并真实试音。该测试会下载大文件，生成的日志、报告及模型只在 `.test-data/downloads/`。下载源探测仅说明当前可连接，不代表整包下载、国内全部运营商或 Windows / Intel 实机验证。

购前检测为可选自查，不作为购买或签发条件。签发仅需客户设备码；命令为 `node scripts/license-admin.cjs issue 客户机器码`，已购补发可保留 `--replacement`。HTML 工具同样不要求检测报告。报告仍可用于排查兼容性问题，不具备防篡改认证。

M 系列 Mac 已完成全新目录自动安装组件、下载轻量模型和真实试音；Intel x86 环境在 Rosetta 下生成成功，尚不等于 Intel 实机验收。发行签名、公证、目标硬件与低内存验收仍须完成。

## 构建

需要 Node.js 22.12+、npm。执行 `npm install`、`npm run resources`，然后 `npm start`。Mac 构建执行 `npm run build:mac`，Windows 构建执行 `npm run build:win`。Windows 正式发行建议在 Windows 构建并完成实机验收、代码签名；Mac 正式发行需 Developer ID 签名和 Apple 公证。

Mac 签名必须保留 `Contents/Resources/uv/` 中两份上游原始安装器的字节与原有签名，由 `mac.signIgnore` 精确排除这两个文件；运行时仍校验完整 SHA-256。`afterSign` 会再次检查签名后的所有安装器，发现重签名导致的内容变化时阻止产出安装包。可执行 `VOICE_STUDIO_TEST_RESOURCES="/absolute/path/声悦.app/Contents/Resources" npm run test:setup:packaged`，使用最终签名包内的真实 uv 验证 ASAR 安装、失败、取消及临时文件清理；该测试不下载声音模型。

本次目标 Mac arm64 / Mac x64 / Windows x64。Intel 使用独立 CPU 依赖；Windows ARM、Linux 未适配。

测试：`npm test`、`npm run test:activation`、`npm run test:session`、`npm run test:ui`；已配置本地模型与 Python 时执行 `npm run test:desktop`。开发可设置 `VOICE_STUDIO_PYTHON` 与 `VOICE_STUDIO_DATA`，避免写入用户真实数据。

CLI：`node cli/studio.cjs --help`，协议与集成方式见 [Agent 与 CLI 调用](Agent-CLI.md)。`npm test` 包含 CLI 的子进程协议、并发锁、共享激活状态、取消、超时与导出测试。桌面和 CLI 使用同一 `desktop/service.cjs`；安装包包含 `cli/`，以 `--cli` 参数进入无窗口模式。

## 离线授权

客户端以 ASAR 内的 `desktop/trust-anchor.cjs` 为固定信任来源，Python 引擎内置相同公钥；`shared/license-public.pem` 仅供商家与构建一致性检查，替换外部 PEM 不能解锁发行版。使用 Ed25519 校验与机器码绑定的现有 SY2 授权，永久专业版不访问授权服务器。机器码从 Mac IOPlatformUUID / Windows MachineGuid 派生；支持的平台读取失败时拒绝降级到可复制的安装标识。

v0.4.1 将 backend / shared 一并放入 ASAR，启用 `EnableEmbeddedAsarIntegrityValidation` 和 `OnlyLoadAppFromAsar`，同时关闭 RunAsNode、NODE_OPTIONS 和主进程 inspector。发行版禁止远程调试启动参数及 renderer DevTools。Python 运行前从受保护归档复制到本次进程专用的临时目录，结束后清理；不使用外部松散 worker，也不使用环境变量指定的解释器。随包 uv 执行前验证固定 SHA-256，子进程移除 Python、Node、动态加载器和安装源覆盖环境。

Mac 的 afterPack 用系统 clang 为对应 arm64 / x86_64 编译 `native/archive-guard.c`，将本次完整 app.asar SHA-256 固定到原生 dylib，并将主程序对 Electron Framework 的依赖改为经由该校验模块重导出。构造函数在 ElectronMain 前核对归档；同时修改 ASAR 和 Info.plist 中的校验值仍返回 78。该模块随后与应用一并签名；更改归档必须重新构建，不能在 afterPack 后修改归档。Windows 使用 Electron 原生 PE INTEGRITY/ELECTRONASAR 资源保存归档头摘要。控制本机后替换、重新编译或重新签名原生代码仍属于剩余边界。

Python 对生成、合成、导出、声音导入与捕获独立验签；生成每段前及推理结束、写入作品前再次校验。未授权 status 隐藏作品与参考声音；固定文案 diagnose 继续用于购前试音，不开放任意文案。新增 cryptography 46.0.3，三个平台锁文件分别更新，保留原签发密钥及激活码协议。

构建前检查桌面、公钥文件与 Python 内置公钥一致，禁止将私钥打入 backend / shared；执行 `npm run test:security` 和 `npm run test:release-security` 回归公钥替换、改包、重封包、目录替换、调试注入、直接 worker 调用和离线合法使用。发行版禁止用于 Playwright 的主进程调试，界面交互回归通过开发 fixture，正式窗口另用原生 UI 检查。

当前无正式签名证书：Mac 为带 hardened runtime 的 ad-hoc 签名，因 Electron 框架缺少统一 Team ID，保留 disable-library-validation 例外；使用真实 Developer ID 对所有嵌套代码签名后应移除此例外并完成公证。Windows 未配置 Authenticode。拥有本机控制权的人仍可能修改、重新签名或重写引擎；本方案不保证绝对不可破解，也不改变永久离线授权无法远程撤销的限制。

签发私钥在 `.seller/signing-key.pem`，已生成，禁止重新初始化或覆盖。请自行离线备份。私钥不在源码 ZIP、客户端或商家工具 ZIP 中。

打开 `seller-tools/声悦激活码签发.html`，选择私钥、粘贴客户机器码并签发；该工具可断网运行。也可执行：

```sh
node scripts/license-admin.cjs issue 客户机器码
```

v0.3.1 为强制激活版，不提供免费生成体验。未激活时只开放授权查询、激活、复制设备码、购买说明、日志和第三方声明；不加载工作台、不启动 Python 引擎。桌面 IPC 与共用服务层均拦截功能调用，CLI 返回 LICENSE_REQUIRED（退出码 5）；后台任务在提交和执行前校验，未激活时保留排队任务，激活后恢复。使用新版 SY2 90 位激活码，不兼容旧 SY1 码；旧 usage.json 不参与授权判断。订单信息另存销售记录，激活码只包含绑定设备的永久专业版签名。

激活后不限制生成数量。永久离线授权不能远程撤销，也不能严格强制换机次数；客户端可被修改，签名授权不保证不可破解。订单、换机与退款由销售渠道管理。客户端已接入微信联系二维码，激活页、购买帮助和设置页共用本地扫码弹窗；官网对应语言的“联系我们”展示同一原图。

目前未接入在线收款、订单系统、自动更新、崩溃上报；销售安装包可通过你自己的下载站或分发平台提供，客户激活和日常使用不依赖它。

## 语音引擎与许可

底层使用 Qwen3-TTS：CustomVoice 标准与轻量、VoiceDesign 人物设计、Base 参考复用。Mac 使用 MLX Audio 4-bit 转换权重，Windows 使用官方 PyTorch 权重；默认 CPU，若运行环境安装兼容 CUDA 则自动选 GPU。程序按需切换模型，释放前一个模型。

官方资料：https://github.com/QwenLM/Qwen3-TTS 。精选音色为官方 9 款；童声通过 VoiceDesign 生成，不属于固定说话人。轻量 0.6B CustomVoice 不提供指令表演控制；Base 复用不提供额外表演指令。正常界面只展示产品能力，底层名称保留于开发资料、诊断日志与第三方声明。

模型和官方代码 Apache 2.0，MLX Audio 为 MIT，其他组件许可独立适用。本项目现有源码许可 MIT；商业销售前应制定你的产品使用条款与售后规则，保留第三方许可。上游模型许可并不替代参考声音与输出内容的权利确认。

产品名“声悦”尚未核验商标。正式上架还需：品牌核验、发行签名 / 公证、Windows 实机验收、销售条款和客服渠道。

## 面向普通用户的声音选择

声音库提供按用途筛选与推荐场景标签，试听使用随包附带的 36 个录音；激活后即使未装声音包或离线时仍可听内置示例。人物示例是声音创作的参考，修改声线描述后不自动录制新的试听。自定义声音需先正常生成、存为声音，再试听保存的原始录音。

创作页默认展示文字、声音、用途和常用语气，技术参数放在“更多设置”。如果未安装对应声音包，生成入口会引导安装。参考了 [MiniMax 音色库](https://www.minimax.cn/audio/voices) 的选声描述与标签，以及 [豆包](https://www.doubao.com/chat/) 的直接输入入口和面向普通用户的表达；本次未进入需要登录的豆包语音功能，也未复制品牌资产。

回归检查：`npm run test:consumer` 校验素材、场景标签、激活后离线试听、录音复用和筛选逻辑；`npm run test:desktop` 为桌面完整流程测试。

## 当场录音

「我的声音」保留导入入口，并提供「直接录音」。录制 3–30 秒，支持实时音量反馈、自动停止、试听和重录；填写声音名称及准确原话后保存。录音转换成单声道 PCM WAV，通过现有参考声音导入流程统一重采样和持久化，不调用配音引擎。取消、重录、失败与关闭页面都会停止麦克风并释放临时资源。

Electron 只在用户点击开始录音后，为应用自己的主页面放行音频权限；摄像头和其他权限仍拒绝。macOS 包配置 `NSMicrophoneUsageDescription`，系统麦克风授权仍由用户决定。录音、原话和音色资料仅保存在本机；无需上传或填写云服务密钥。`tests/recording.test.cjs` 覆盖时长、取消、错误恢复、权限范围、WAV 校验和临时文件清理。

Windows 在直接录音和购前麦克风检测前，通过 Electron 的 `getMediaAccessStatus('microphone')` 检查系统访问状态。拒绝时提示在 Windows 设置的“麦克风”页面开启“麦克风访问权限”和“允许桌面应用访问麦克风”；系统策略限制时提示联系管理员。状态未确定时继续正常请求录音，重试会重新检查。静音录音提示检查默认输入设备、输入音量和静音开关；程序不修改系统隐私设置。权限依据：[Electron API](https://www.electronjs.org/docs/latest/api/system-preferences#systempreferencesgetmediaaccessstatusmediatype-windows-macos)、[微软麦克风权限说明](https://support.microsoft.com/zh-cn/windows/privacy/turn-on-app-permissions-for-your-microphone-in-windows)。

`npm run test:recording` 使用隔离的 Electron 和 Chromium 模拟麦克风验证音量反馈、真实 MediaRecorder / WebM 解码、WAV、试听、参考声音保存、权限拒绝提示及重试取消。系统权限状态分支由单元测试注入验证；这些检查不替代 Windows 实机的物理麦克风、隐私开关和驱动验收。

## v0.3.2 声音与场景扩充

包含 9 款固定音色、27 个人物声音设计预设、20 套场景模板。模板库支持分类、搜索、预存试听、套用和撤销；批量、逐句角色、文件名及完整表达设置均可进入既有任务流程。声音库支持原生语言筛选与多关键词搜索，并优先展示当前用途的专门声线。

新增 15 个预设在本机录制试听，按推荐用途配置表达，试听统一目标 RMS 并修剪过长首尾静音，峰值保留余量；只处理内置试听，用户生成音频的既有导出行为不变。`scripts/build-previews.py` 按内容指纹复用录音，`scripts/sync-website-assets.py` 同步网站声音、配图和波形。`scripts/create-catalog.py` 刷新时保留扩展预设、模板及录音元数据。
